# curator-codex-agent

**Unified Code + Documentation Curator**. Recursively analyzes both source code files AND documentation (.md, .txt), discovers associated files, and extracts structured knowledge into enterprise vaults using LLM reasoning.

## Quick Start

```bash
# Analyze entire project (code + docs)
CURATOR_INPUT_PATH=/project \
CURATOR_OUTPUT_PATH=/vault \
CURATOR_API_KEY=sk-... \
npm run watch-code
```

## Core Capabilities

1. **Unified Processing** — Analyzes both code (.ts, .js, .py, etc) AND docs (.md, .txt) in single pass
2. **Multi-language Code Analysis** — TypeScript, JavaScript, Python, Go, Rust, Java, C/C++, Kotlin, Swift
3. **Documentation Analysis** — Extracts policies, procedures, decisions, lessons from .md/.txt
4. **Smart Documentation Discovery** — Finds and combines associated .md files, README.md, project context
5. **Automatic Type Detection** — Routes files to appropriate analyzer (CodeAnalyzer or DocumentationCurator)
6. **Reasoning-based Extraction** — Uses deepseek-reasoner for deep understanding
7. **Change Detection** — Manifest-based tracking; only reanalyzes changed files
8. **Vault Integration** — Outputs semantic markdown notes with metadata
9. **MCP Server** — Runs as stdio or HTTP MCP server

## Key Features

- ✅ Recursive directory scanning
- ✅ Public API extraction (types, functions, classes, interfaces)
- ✅ Pattern & architecture detection
- ✅ Dependency mapping
- ✅ Documentation association (code.ts + code.md → combined analysis)
- ✅ Change tracking via SHA256 manifest
- ✅ Efficient reprocessing (skip unchanged files)
- ✅ Multi-provider support (DeepSeek, OpenAI, Anthropic, Ollama)

## Environment Variables

**Required:**
- `CURATOR_API_KEY` — LLM API key
- `CURATOR_OUTPUT_PATH` — Vault output directory

**Optional:**
- `CURATOR_INPUT_PATH` — Code directory to analyze once (default: watch mode)
- `CURATOR_PROVIDER` — LLM provider (default: deepseek)
- `CURATOR_MODEL` — Model ID (default: deepseek-reasoner)
- `CURATOR_PORT` — HTTP port for MCP (default: stdio transport)

See `.env.example` for all options.

## Architecture

```
CodeAnalyzer
├── findAssociatedDocs()     — Discovers code.md, README.md, etc
├── analyzeFile()            — Analyzes single file + combined docs
├── callLLM()                — Sends to reasoning model
└── writeNote()              — Outputs to vault

Manifest System
├── calculateFileHash()      — SHA256 tracking
├── loadManifest()           — Read .codex-manifest.json
├── hasFileChanged()         — Detect changes
└── saveManifest()           — Update tracking
```

## Usage Modes

1. **Direct Analysis** (single run):
   ```bash
   CURATOR_INPUT_PATH=/project npm run watch-code
   # Analyzes once, exits
   ```

2. **Watch Mode** (continuous):
   ```bash
   npm start
   # Polls vault/incoming/ every 30s
   ```

3. **MCP Server**:
   ```bash
   CURATOR_PORT=3101 npm start
   # HTTP MCP server
   ```

## Performance

- 3-8 seconds per file (reasoning model)
- Skipped files: < 100ms
- 500 files, 1st run: ~40-60 min
- 500 files, 2nd run (1% changed): ~2-3 min

## Architecture

```
CodeAnalyzer
├── analyzeFile()          — Dispatcher
├── analyzeCode()          — Route to CodeAnalyzer
├── analyzeDocumentation() — Route to DocumentationCurator
├── isDocFile()            — File type detection
└── findAssociatedDocs()   — Discover code.md, README.md

DocumentationCurator (embedded)
├── curateFile()
├── curateText()
└── callLLM()              — Extract policies, procedures

Manifest System
├── findAllFiles()         — Find code + docs (recursive)
├── isCodeFile()           — Detect .ts, .js, .py, etc
├── isDocFile()            — Detect .md, .txt
└── Change tracking        — .codex-manifest.json
```

## Comparison

| Feature | curator-agent | curator-codex-agent |
|---------|---|---|
| **Input** | .md, .txt docs only | Code + Docs (.ts, .js, .py, .md, .txt) |
| **Code Analysis** | ❌ No | ✅ Yes (extract APIs, components) |
| **Doc Analysis** | ✅ Yes | ✅ Yes (extract policies, procedures) |
| **File Detection** | Manual separation | Automatic file routing |
| **Associated Docs** | N/A | ✅ Finds code.md, README.md |
| **Use Case** | Docs-only projects | Projects with code + docs |
| **Workflow** | Sequential | Unified (one pass) |

## When to Use Each

| Scenario | Use |
|----------|-----|
| I have code + docs (mixed project) | **curator-codex-agent** ← unified |
| I ONLY have documentation files | curator-agent |
| I ONLY have code (no docs) | curator-codex-agent |
| I want code analysis only | curator-codex-agent (will skip .md) |
| I want docs analysis only | curator-agent |
